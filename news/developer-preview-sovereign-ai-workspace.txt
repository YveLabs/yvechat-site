3:T19de,<p>YveChat has opened the developer preview of its sovereign AI workspace, bringing its core local architecture into a working product environment where models, conversations, and compute can remain on hardware controlled by the user.</p>
<figure class="np-media np-video"><video src="/news/media/developer-preview.mp4" controls playsinline preload="metadata" aria-label="YveChat, the sovereign AI workspace"></video><figcaption>Your models. Your machine. Your workspace.</figcaption></figure><p>The developer preview connects the hosted YveChat workspace with YveChat Engine, a local process running on the user&#39;s computer. The workspace provides the interface for conversations, model selection, tools, and citations. The Engine handles local runtime discovery, model requests, conversation storage, and other operations that require access to the user&#39;s machine.</p>
<p>When a local model is selected, inference runs through the user&#39;s own hardware. Conversations are persisted by the Engine to a local SQLite database, keeping the working history on the user&#39;s disk.</p>
<p>The release marks the latest step in YveChat&#39;s broader goal of applying self-custody principles to AI.</p>
<h2>From browser to local machine</h2>
<p>At the center of the architecture is YveChat Engine.</p>
<p>A hosted browser interface faces practical restrictions when communicating directly with software running on a local computer. Browser local-network policies, cross-origin restrictions, and runtime configurations can create inconsistent access to services such as Ollama. YveChat Engine provides the local boundary between the workspace and those resources.</p>
<p>Users pair the workspace with their Engine through a six-digit code approved on their own machine. Pairing is origin-bound and includes expiry and revocation controls. Once connected, the Engine can discover supported runtimes and expose available models to the workspace.</p>
<p>The resulting flow keeps the major components clearly separated:</p>
<ul>
<li><strong>Workspace:</strong> threads, model selection, tool activity, and citations</li>
<li><strong>YveChat Engine:</strong> runtime discovery, routing, secrets, tool execution, and local persistence</li>
<li><strong>Runtimes:</strong> Ollama and compatible model endpoints</li>
<li><strong>Storage:</strong> conversations and settings managed locally through SQLite</li>
</ul>
<p>For local Ollama conversations, prompts are routed from the workspace through the Engine to the model running on the user&#39;s hardware. Responses stream back through the same path, and the completed thread is persisted locally.</p>
<h2>Local AI as a working path</h2>
<p>Ollama-served language models are available in the developer preview, allowing supported open-weight models to run directly on user hardware without provider credentials.</p>
<p>Dynamic model discovery allows the Engine to identify models available through the local runtime. Validated Ollama model downloads are also supported, giving users a more accessible route to expanding the models available inside their workspace.</p>
<p>Local image generation extends the same approach into Image Studio through ComfyUI.</p>
<p>Other available capabilities include web search with citations through Ollama Web Search and SearXNG, local conversation storage, local accounts, optional wallet authentication, browser pairing, configured origin controls, and capability filters.</p>
<p>The architecture is designed so that sovereignty properties can be observed through the system itself. Local inference can be verified through network activity, conversation storage can be inspected on disk, and the Engine creates a visible boundary for operations involving local resources.</p>
<h2>Identity can stay with the user</h2>
<p>The developer preview supports local accounts alongside optional wallet authentication.</p>
<p>Wallet authentication uses a signature as identity, giving users a path to access based on credentials they control. Local accounts remain available for users who prefer a conventional login within their own environment, with passwords protected using scrypt hashing and a minimum-length requirement.</p>
<p>Together, these options form part of YveChat&#39;s broader custody model across compute, data, access, and identity.</p>
<h2>Available today and still being built</h2>
<p>YveChat is releasing the workspace as a developer preview while development continues across the wider architecture.</p>
<h3>Available</h3>
<ul>
<li>Local language models served through Ollama</li>
<li>Dynamic model discovery</li>
<li>Validated Ollama model downloads</li>
<li>ComfyUI local image generation</li>
<li>Web search with citations</li>
<li>Local SQLite conversation storage</li>
<li>Local accounts</li>
<li>Optional wallet authentication</li>
<li>Six-digit browser pairing</li>
<li>Origin policy and capability filters</li>
</ul>
<h3>Experimental</h3>
<ul>
<li>OpenAI-compatible endpoints using a manually configured base URL</li>
<li>vLLM through the OpenAI-compatible adapter</li>
<li>Page reading and extraction tools</li>
<li>PDF reading</li>
</ul>
<h3>Planned</h3>
<ul>
<li>Full hosted model-provider credential management</li>
<li>MCP connections with per-tool permissions</li>
<li>Sandboxed code execution</li>
<li>Local file and document retrieval</li>
<li>Additional utility and data adapters</li>
<li>User-configurable external storage</li>
<li>Public signed and notarized installers with automatic updates</li>
</ul>
<p>This distinction will remain part of how YveChat reports development. Features will continue to be identified according to their actual stage as available, experimental, or planned.</p>
<h2>The developer preview moves forward</h2>
<p>The current release represents the working foundation of the YveChat architecture while public installers and broader onboarding continue toward release.</p>
<p>The Custody era is complete, and YveChat is currently in the Engine era. The unsigned developer-preview archive is available today, while signed production installers remain planned. Page and PDF reading are Experimental through the gateway layer. Broader Gateway-era capabilities remain ahead, including permission-controlled actions, MCP connections, sandboxed execution, and broader credential management.</p>
<p>Each stage follows the same principle established by the developer preview: control should remain observable and understandable to the person using the system.</p>
<p>YveChat&#39;s direction can be stated simply.</p>
<blockquote>
<p>Your models. Your machine. Your workspace.</p>
</blockquote>
